# Функции на основе ИИ — тренажёр аналитика

Двенадцать тем на вымышленном ассистенте поддержки интернет-магазина «Полка»: где модель уместна, а где
дешевле формула; как переписать «должен корректно отвечать» в проверяемый вид; какой порог качества
и что делать ниже него; из чего собирается набор для проверки; откуда берутся факты и какие данные
нельзя отдавать внешней модели. Ещё три темы — про проект вокруг функции: как оценить срок, когда
половина работы — исследование; какие риски у ИИ-проекта и как не дать объёму расползтись; сколько
стоит один ответ, сделать функцию и содержать её. И три последние — про жизненный цикл: какие идеи
вообще брать и как пройти от демо до эксплуатации; как проверять и выкатывать новую версию через
ворота; что мерить после запуска, как замечать дрейф и что откатывать вместе.

Открывается двойным щелчком по `index.html` — ни сборки, ни сервера. Так же он раздаётся с
GitHub Pages и так же встраивается в платформу.

## Что внутри

| Вкладка | Симулятор | Задания |
|---|---|---|
| Задача | один вопрос десять раз: формула против модели | вероятностная задача или обычная |
| Требование | конструктор требования из кусков; вопрос, на который ответа нет | проверяемая формулировка, поведение при неуверенности |
| Порог | порог на 400 обращениях с ценой обеих ошибок | два вида ошибки, критерий приёмки, сторона порога |
| Набор примеров | поймает ли ваш набор выкаченную поломку | почему демонстрация не доказательство, состав набора, трудные случаи |
| Источники | ассистент отвечает по документам: что найдено и что в ответе | из документов или из модели, состав источников |
| Данные и модель | конструктор запроса с маскированием: что уедет наружу | что уходит наружу, чего быть не должно |
| Оценка | оценка тремя числами (PERT), воронка неопределённости с развилкой «опыт не сработал», структура работ «прожить полгода», исследование с ограничением по времени | расчёт оценки, срок на этапе постановки, забытые пакеты работ, карточка исследовательской задачи |
| Риски | реестр рисков на сетке «вероятность × влияние» с реакциями, четыре функции NIST AI RMF, запрос на изменение, скрытый долг вокруг модели | риск по признаку, мера против риска, функция NIST, порядок работы с запросом на изменение, что сопровождать |
| Смета | стоимость вопроса по ходам агента, безубыточность API / свой сервер / бесплатный тариф, видеопамять под свою модель, стоимость владения, юнит-экономика ответа, диалог с финансовым директором | стоимость вопроса, точка безубыточности, видеопамять, разовые и ежемесячные, окупаемость ответа, сильный аргумент |
| Стадии | карточка оценки ИИ-идеи (свои ответы против разбора), четыре стадии от демо до эксплуатации с развилками «не лучше простого решения» и «код пробы в MVP», конструктор плана пробы с тремя исходами, три договора под неопределённость | отсеять слабую идею, решающее число стадии, решение по итогам пробы |
| Выпуск | ворота выкатки с выбором поломки и убранными воротами, сигнальный набор против четырёх смен, чемпион и претендент по темам и каналам, «что поменялось — какие ворота заново», приёмка защитного фильтра по двум ошибкам, выкатка подсказки на долю обращений с откатом | путь новой версии, состав сигнального набора, выкатывать ли претендента, что проходим заново, приёмка фильтра |
| После запуска | панель живых метрик и их слепые пятна, восемь недель с акцией, сменой правил и обновлением модели, откат по частям и целиком, отзывы превращаются в эталоны, калькулятор сопровождения со сверкой со «Сметой» | какое число покажет первым, что поплыло, что откатываем вместе, сколько стоит сопровождение |

Сорок заданий, у части — лестница подсказок. Раскрытая подсказка уменьшает вес
доказательства, но не обнуляет его. Виды заданий: выбор одного, выбор нескольких, сопоставление,
число (поле ввода, проверка с допуском) и цепочка (собрать шаги по порядку, лишние не брать).
Цены, сроки и числа на вкладках «Оценка», «Смета», «Стадии», «Выпуск» и «После запуска» условные — это
пример, в поля можно вписать свои.

## Связь с платформой

Тренажёр отчитывается о решённых заданиях платформе T-shape, когда открыт внутри неё. Наружу уходит
только факт: код задания, номер успешной попытки и число раскрытых подсказок. Какой индикатор графа
навыков подтверждает задание — знает платформа, у неё лежит манифест
(`apps/web/src/content/trainers/aiFeature.ts`). Протокол `trainer/1`, обмен через `postMessage`;
подробности — в README тренажёра по персональным данным и в документе платформы
`docs/09-trainer-contract.md`.

Вне платформы работает полностью: прогресс хранится в браузере, отчитываться просто некому.

## Как добавить задание

1. Сначала — в платформе: строка в манифесте (код задания, название, индикатор графа, тип
   доказательства, число ступеней подсказок).
2. Потом — здесь: запись в массиве `TASKS` с тем же кодом и полем `panel` — вкладкой, на которой
   оно появится.

Порядок важен: задание, о котором платформа не знает, не засчитается — молча. Число подсказок в
двух местах должно совпадать: платформа не примет сообщение, где подсказок больше, чем в манифесте.
