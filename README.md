# Функции на основе ИИ — тренажёр аналитика

Шесть тем на вымышленном ассистенте поддержки интернет-магазина «Полка»: где модель уместна, а где
дешевле формула; как переписать «должен корректно отвечать» в проверяемый вид; какой порог качества
и что делать ниже него; из чего собирается набор для проверки; откуда берутся факты и какие данные
нельзя отдавать внешней модели.

Открывается двойным щелчком по `index.html` — ни сборки, ни сервера. Так же он раздаётся с
GitHub Pages и так же встраивается в платформу.

## Что внутри

| Вкладка | Симулятор | Задания |
|---|---|---|
| Задача | один вопрос десять раз: формула против модели | вероятностная задача или обычная |
| Требование | конструктор требования из кусков; вопрос, на который ответа нет | проверяемая формулировка, поведение при неуверенности |
| Порог | порог на 400 обращениях с ценой обеих ошибок | два вида ошибки, критерий приёмки, сторона порога |
| Набор примеров | поймает ли ваш набор выкаченную поломку | почему демонстрация не доказательство, состав набора, трудные случаи |
| Источники | ассистент отвечает по документам: что найдено и что в ответе | из документов или из модели, состав источников |
| Данные и модель | конструктор запроса с маскированием: что уедет наружу | что уходит наружу, чего быть не должно |

Тринадцать заданий, у части — лестница подсказок. Раскрытая подсказка уменьшает вес доказательства,
но не обнуляет его.

## Связь с платформой

Тренажёр отчитывается о решённых заданиях платформе T-shape, когда открыт внутри неё. Наружу уходит
только факт: код задания, номер успешной попытки и число раскрытых подсказок. Какой индикатор графа
навыков подтверждает задание — знает платформа, у неё лежит манифест
(`apps/web/src/content/trainers/aiFeature.ts`). Протокол `trainer/1`, обмен через `postMessage`;
подробности — в README тренажёра по персональным данным и в документе платформы
`docs/09-trainer-contract.md`.

Вне платформы работает полностью: прогресс хранится в браузере, отчитываться просто некому.

## Как добавить задание

1. Сначала — в платформе: строка в манифесте (код задания, название, индикатор графа, тип
   доказательства, число ступеней подсказок).
2. Потом — здесь: запись в массиве `TASKS` с тем же кодом и полем `panel` — вкладкой, на которой
   оно появится.

Порядок важен: задание, о котором платформа не знает, не засчитается — молча. Число подсказок в
двух местах должно совпадать: платформа не примет сообщение, где подсказок больше, чем в манифесте.
